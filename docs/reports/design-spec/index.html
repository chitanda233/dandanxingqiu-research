逆向策划设计案

主循环、规则、成长、匹配与经济的整体复原

缓存版本 2422026-09-30源码可回查

弹弹星球逆向策划设计案

本案按客户端原始字节码、有效配置和受控函数执行复原。每个模块的规则、状态、数据和边界见各专题。

本版设计案的复原方法

从缓存原包取8272个Lua字节码；白名单静态配置执行时展开行元表默认值；行为模块生成184个原指令列表，遇到反编译条件丢失时直接核对跳转与寄存器。35个明确输入的受控场景执行原始函数，覆盖技能资格/升级、蓄力公式、宠物衰减和通行证双轨领取。原包哈希、配置来源、函数输入和返回均留在仓库；这不是在线账号测试。配置来源、原指令来源、函数执行证据

本轮纠正了一类系统性错误：Lua配置行只写差异字段，完整字段经元表继承。此前排位自动/技能开关、40级技能成本、60级经验、武器高阶品质被当成缺失，现在按有效配置重导。分服片段也不再代替基础表：任务7004条＋覆盖80条，商店2529条＋覆盖23/28条，开放707条＋覆盖片段。

产品循环的具体设计

玩家先接收服务器/云数据与功能开放列表，主城根据权限展示系统入口；任务把角色引导到实际玩法和培养页。成长提升点数预算、武器档位、宠物与技能构筑；入排时检查开放/时间/队伍，并可提示未激活或严重落后模块。匹配成功后等待战斗进入消息，回合消息给行动者和时钟；玩家通过移动/角度/蓄力/技能生成操作输入。服务器返回表现节点和属性结果，再给胜负、杯数与资源更新。日常活跃与通行证双轨奖励驱动资源再次投入。

这条循环里有五套互不替代的状态：功能已开放、养成已解锁、构筑已装备、局内技能可用、奖励已领取。角色够级但云端关闭、拥有技能但当前计划未装、CD已好但次数耗尽、通行证达级但未买付费轨，都会得到不同的可操作结果。

可复算的一条成长与战斗路径

  1. 角色22级时检查1001当前0级行、开放/前置与解锁书；0→1花书，后续消耗由当前等级行读取。培养成功写新等级，不凭按钮动画装备。
  2. 选择当前玩法技能计划和槽位，生成具体cf_skill_id；进入排位102后技能允许、手动自动战斗关闭、不能倍速、没有超时保底发炮。
  3. 本人action回合用冰冻1001009：还要非沉默、非重复回合、CD0、回合次数<1、单局次数<1、strength足够；费用0也不绕过这些资格。
  4. 开始蓄力停移动并上报force_speed；P100/A0/无环境buff时原函数S.181818，上报1818。发炮再提交实际angle/force与位置快照。
  5. 分批node_list全到齐才播放；HP按更新夹在0..max_hp。若发炮请求失败，清round_fired/发射信息并取消holding，剩余行动时间仍按服务器回合时钟。
  6. 结果回包决定win_camp，外围另更新奖励和杯数；免费通行证6级奖在当前10级/已领5级时可领，付费4级奖则还要求is_buy与advance_level<4。

这些步骤均有具体数据或函数分支支撑。仍未持有服务端部分的环节直接列出缺口，不填成“常见设计应该如此”。

数据与页面如何使用

每个专题的正文先说明对象、前置、流程、失败、回包与数值意义；后面是计算后可读的完整表。长表折叠，保留全行数据与源链接，资源尽量显示中文名＋ID。原始包在raw，提取/反编译/指令在reverse，报告与执行导出在analysis，网页在docs；研究内容与原始资源分离。

当前报告基于缓存版本242，不把历史、测试或不可达开放条件的记录当在线玩法。原指令不是新的源代码，LuaDec/unluac仍可能失真；正文关键分支优先用原指令和明确输入执行结果复核。
